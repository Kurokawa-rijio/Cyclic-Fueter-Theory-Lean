## Overview

This repository contains Lean 4 formalizations associated with the research program *Cyclic Fueter Theory* (CFT) and the author's claim ledger α-I–α-VIII. The code covers quaternionic algebra, matrix and spinor constructions, quantum-geometric identities, Cartan-frame calculations, spherical Einstein–Yang–Mills (EYM) reductions, junction calculations, constraint propagation, zero-mode calculations, and selected links to WZW and related geometric formulas.

The source snapshot was supplied as `CFT_alpha_lean_2026-10-17b.zip`. The inherited project audit reports 706 theorem declarations, including 109 auxiliary polynomial identities used in the α-II.5 calculations. This count is a count of declarations, **not** 706 independent research claims.

## Important scope statement

Lean checks that each theorem follows from its formalized assumptions. It does not automatically validate whether those assumptions correctly model a physical system, whether an imported theorem applies to the research setting, or whether a numerical result is an exact solution of the field equations.

The latest author-maintained status ledger (2026-10-18) classifies the 51 items as:

| Status | Count | Meaning |
|---|---:|---|
| Complete, including items that rely on a stated external theorem | 25 | The ledger considers the formalized statement complete at the stated scope |
| Partial | 17 | The Lean statement is weaker than the full claim |
| Conditional | 5 | A key hypothesis or external result remains assumed |
| Not formalized as stated | 4 | The formalized object differs from, or does not yet cover, the ledger claim |

These are **author-maintained research classifications**, not peer-review results. The checked-in `review/` and `audit*.txt` files include historical audit material; some snapshots predate the status ledger above. Please consult the per-claim notes rather than treating the summary count as a proof of every corresponding physical claim.

The project also contains calculations that treat `W = r'` as an additional condition on time-symmetric initial data. That condition is not established as a dynamically invariant sector of the full EYM system. Likewise, a constructed initial-data profile should not be described as a complete spacetime solution unless the evolution equations and relevant boundary conditions have also been verified.

## Build

Install [Elan](https://github.com/leanprover/elan) and Git. From the repository root:

```bash
lake update
lake exe cache get
lake build
```

The `lean-toolchain` file pins Lean 4.15.0. `lakefile.lean` uses Mathlib tag `v4.15.0`; the former archive's Lake manifest referenced a local `../mathlib4` path, so that manifest was intentionally removed and should be regenerated by `lake update` on the public repository.

To run the theorem-axiom audit file after dependencies have been installed:

```bash
lake env lean Audit.lean
```

A GitHub Actions workflow under `.github/workflows/lean.yml` runs a build on pushes and pull requests. Until that workflow passes on the published repository, do not describe this prepared snapshot as newly rebuilt in CI.

## Repository layout

- `CFT/` — Lean modules grouped by the α claim families and supporting calculations.
- `CFT.lean` — umbrella module importing the main formalization.
- `Audit.lean`, `audit.txt`, `audit_raw.txt` — axiom-audit source and inherited audit output.
- `review/` — claim ledgers and a per-claim audit table supplied with the source snapshot.
- `docs/CLAIM_STATUS_JA.md` — latest 51-item status ledger supplied by the author.
- `docs/archive/` — historical README and build log from the source package.

## Reproducibility and external results

Some claims explicitly rely on external mathematical or physical input, including field-equation formulas, geometric identities, or cited classification results. Such dependencies are described in the relevant Lean modules and audit notes. The formal code should be read together with those assumptions and the per-claim status ledger.
