## 0. 前提として確認したこと

- **存在しない「定理」**:README の定理名のうち `classify`、`scalR`(α-III.9)、`sqDensity`(α-VIII.2)は `theorem` ではなく `def` である(AlphaIII_Junction.lean 29・35 行、AlphaVIII_Embedding.lean 75 行)。それ以外の名前とワイルドカード(`cod*`、`fs*`、`cf…_k…` = `cfk0_k0` など 109 個)はすべて見つかった。
- `sorry` と独自の `axiom` は grep で 0 件。`audit.txt` には sorryAx が現れず、公理は標準の 3 つだけ。
- **ビルドの証跡が古い**:`build_all.log` の日付は 10-15 22:45 で、その後 10-16 に 30 本近いソースが更新されている。ローカルの `.lake/build/lib/CFT` には AlphaCompleteA/B/C2、AlphaIntegrals、AlphaIII_Junction、AlphaVIII_BPS、AlphaVII_Bundle/Chirality、ZeroModeL2、Cartan/SS* などの olean がない。`audit.txt`(10-16 12:29)はすべての定理を挙げているので、別の環境でビルドしたものと思われる。ただし「全体がエラーなしでコンパイルされる」ことを、この監査では手元で確かめられていない。
- **台帳に存在しない出典コード**:Z_ledger.md には Z1〜Z46 しかない。Z0、Z0′、Z0-f、Z0-m、Z4-1/2/3/D/E、Z9-a/c、Z10′、Z18-a、Z28-d、Z28-f、「U21′ 監査」、N1、「台帳 40022e17」はどれも台帳ファイルに記述がない。これらの項目は、親項目(Z4、Z9、Z10、Z18、Z28 など)の閉鎖条件と照らし合わせた。

判定の意味:
- **一致**:README の記述と Lean の結論が実質的に同じで、台帳の命題とも大きくずれていない(物理の入力式を定義や仮定として置くのは README の基準どおりで、ここでは許容する)。
- **弱い**:Lean が示すのは数値の恒等式、特殊な場合、模型の計算にとどまり、README や台帳の主張よりずっと弱い。
- **仮定に依存**:核心の恒等式・評価・存在が仮定(または外部の計算・定理)として入っていて、Lean はそこから先の短い代数だけを示している。
- **不一致**:Lean が扱う対象が台帳の命題と別物である。

- Cartan の動標構(Frame)から Bochner 恒等式(`bochner`)を導き、整列型の非存在(`aligned_impossible`)と Bj=0(`Bj_frame`)を示した部分は、二つの公理だけを入力にした本物の代数的導出である。
